**Ordered C build plan, pending your approval:**

1. **Add an additive C migration** under `supabase/migrations/`: cross-workspace FK/constraint enforcement; scoped runtime grants and RLS for `imports`, `dataset_versions`, `source_rows`, `transactions`, and `mapping_corrections`; reviewed `mapping_rules` and structured review-issue storage; durable parse-job metadata; original-workbook retention protection. Add any stale-output marker needed when a version is corrected. Writes: schema/policies, no business rows.
2. **Stage and verify uploads.** Add `backend/app/v2/imports/` and `backend/app/v2/api/routes/imports.py`; extend [router.py](/Users/npvivek/Projects/rice-mill/backend/app/v2/api/router.py:3), OpenAPI and generated frontend types. `POST /v2/imports` derives uploader from JWT and workspace from membership, generates the private object path, and writes `imports`. The browser may calculate a proposed SHA-256; parsing recomputes it from the stored bytes, verifies object owner/path/size, and rejects a mismatch. Use the existing unique `(workspace_id, file_hash)` with conflict handling that returns the existing import, never inserts a second row or overwrites its state. No new migration beyond step 1.
3. **Parse bounded `.xlsx` files into a draft.** Add parser and validation modules in `backend/app/v2/imports/`, parser tests in `backend/tests/`, and sanitized fixtures in `backend/tests/fixtures/`. Write `imports` status, a draft `dataset_versions` row, `source_rows`, and review issues; write **no committed `transactions`** yet. Enforce the spec’s compressed/expanded size, sheet and populated-row caps; preserve coordinates, original Unicode cells, formula/cache warnings and exclusion reasons. New migration: step 1 only.
4. **Make review operational.** `GET /v2/imports/{id}` returns proposed sheet/table/column/date/direction mappings, totals, exclusions and row-linked issues. `review_required` means a parsed draft is awaiting explicit confirmation; unresolved ambiguity prevents commit. Users can correct mappings or explicitly exclude rows, with the decision recorded in `mapping_rules`/`mapping_corrections` and source-row outcomes. Touch `backend/app/v2/imports/`, `backend/app/v2/api/routes/imports.py`, and generated API types. New migration: step 1.
5. **Commit and reconcile atomically.** `POST /v2/imports/{id}/commit` checks membership and expected version, resolves every blocking issue, converts signed/refund values under reviewed rules, and writes `transactions` plus committed `dataset_versions`/`imports` status in one transaction. Use `Decimal`; reconcile included rows to per-sheet and overall totals; distinguish receipts/payments from balances, transfers, invoices and advances. Changed or overlapping workbooks require an explicit independent-dataset versus replace-version choice. Corrections create a new version and audit rows, retaining old source and transaction rows. Touch import service/routes and tests; new migration: step 1.
6. **Expose the ledger and add the v2 UI behind a flag.** Add paginated `GET /v2/datasets/{version}/transactions`, review and correction views, and typed calls in `frontend/src/lib/api/client.ts` and new dashboard components. Keep [the existing browser analyzer and private reports](/Users/npvivek/Projects/rice-mill/frontend/src/components/dashboard/workbook-dashboard.tsx:901) live; do not reinterpret old saved summaries as a complete ledger. The new server parser replaces browser authority **only for v2 imports after review**, with a backend-starting state for Render wake-up. No further migration expected beyond step 1.
7. **Prove C behavior before real-data rollout.** Add fixtures for **refunds** (direction/Decimal reconciliation), **stale formulas** (review warning, no recalculation), **Telugu/English descriptions** (Unicode preservation and mapping), **duplicate totals** (summary/detail exclusion), **invalid dates** (row review), and **overlapping workbooks** (explicit lineage choice). Also test repeated/concurrent same-hash uploads and cross-workspace DB/Storage access. Touch `backend/tests/fixtures/`, import/API tests, and frontend flow tests. Run live C RLS tests and the export/restore drill before enabling family uploads.
